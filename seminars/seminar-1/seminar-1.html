CSS

Как задать оформление страницы?

HTML, в отличие от XML, обладает семантикой, т.е. браузер знает как отображать тот или иной HTML тег. В HTML есть теги для управления внешним видом (font, big, center, ...), но их возможности явно недостаточны, и они устарели.

Решение — описывать внешний вид отдельно от структуры документа c помощью языка Cascading Style Sheets.

Синтаксис CSS

  • Селектор — к каким элементам применить: h1
  • Свойство — что меняем: color
  • Значение — как меняем: navy
  • Пара «свойство: значение;» — объявление
  • Селектор + блок { } — правило

Где могут быть заданы стили?

  • Встроенные в браузер стили (user agent stylesheet)
  • Во внешнем файле — основной способ
    <link rel="stylesheet" href="static/css/style.css">
  • В коде HTML документа
    <style>...</style>
  • В атрибуте конкретного тега — избегаем
    <img style="margin: 3px" src="...">

Порядок подключения важен: сначала bootstrap.min.css, потом свой style.css — так ваши правила смогут переопределить библиотечные.

CSS селекторы

Классы и идентификаторы

  • id — идентификатор элемента, должен быть уникален на странице
  • class — список классов элемента через пробел, классы могут повторяться

На практике стилизуем классами. id оставляем для якорей, <label for> и JavaScript.

Базовые селекторы

  • Универсальный селектор
    * { box-sizing: border-box; }
  • Имена тегов
    p { margin-top: 10px; }
  • Имена классов (с точки)
    .btn { border: solid 1px gray; }
  • id тегов (с решётки)
    #userpic { padding: 10px }

Комбинаторы

  • Потомки на любой глубине (пробел)
    .question-card a { text-decoration: none }
  • Прямые дети (вложенность = 1 уровень)
    .menu > li { display: inline-block }
  • Соседний элемент — сразу следующий
    h2 + p { margin-top: 0 }
  • Все следующие соседи
    h2 ~ p { color: gray }
  • Группировка
    h1, h2, h3 { font-weight: 300 }
  • Несколько условий на один элемент (без пробела!)
    button.btn.active ≠ button .btn .active

Селекторы атрибутов

Удобно стилизовать состояния через атрибуты: та же разметка, что нужна для доступности, управляет видом.

Псевдоклассы: состояния

  • a:link, a:visited ― непосещённая / посещённая ссылка
  • .btn:hover ― элемент под курсором
  • input:focus ― элемент в фокусе
  • :focus-visible ― фокус с клавиатуры (не убирайте outline без замены!)
  • .btn:active ― в момент нажатия
  • input:disabled, input:checked, input:invalid ― состояния полей формы

Каскад и
специфичность

Наследование стилей

Наследуются: color, font-*, line-height, text-align, visibility…

Не наследуются: margin, padding, border, background, width, display…

Заставить: inherit

Поэтому шрифт и цвет удобно задать один раз на body — Bootstrap так и делает.

Каскад: кто победит?

Если несколько правил задают одно свойство одному элементу, браузер сравнивает по очереди:

  1. Важность и источник: !important > стили автора > стили браузера
  2. Специфичность селектора (атрибут style="" сильнее любого селектора)
  3. Порядок: при равной специфичности побеждает правило, которое ниже в коде / в файле, подключённом позже

Расчёт специфичности

Считаем три числа (A, B, C) и сравниваем слева направо:

  • A — количество id
  • B — классы, атрибуты [type], псевдоклассы :hover
  • C — теги и псевдоэлементы ::before
  • * и комбинаторы не считаются; :not(x) и :is(x) — по аргументу, :where() — 0
Селектор(A, B, C)
ul.info ol + li(0, 1, 3)
li.red.level(0, 2, 1)
#userpic a:hover(1, 1, 1)

Специфичность: «баллы» не складываются

Часто объясняют так: id = 100, класс = 10, тег = 1. Для оценки «на глаз» сойдёт, но это не сложение:

Хотите легко переопределять стили — держите специфичность низкой и одинаковой: один класс на правило.

Задачка: какого цвета текст?

Зелёный

p.lead.text — (0,2,1)

А если добавить
.lead { color: orange !important; }?
Оранжевый — !important выигрывает у любой специфичности

Почему !important — плохая идея

  • Перебить !important можно только другим !important — начинается «гонка вооружений»
  • Стили перестают читаться: непонятно, откуда что взялось
  • Ломает утилиты Bootstrap (они сами написаны с !important)

Как переопределить Bootstrap правильно

  1. Подключить свой CSS после Bootstrap
  2. Добавить свой класс: <a class="btn btn-success btn-ask">
  3. Или поменять CSS-переменную: .btn-ask { --bs-btn-bg: #2b9348; }

DevTools — главный инструмент верстальщика

  • F12 / Cmd+Opt+I → вкладка Elements, выбор элемента — Cmd/Ctrl+Shift+C
  • Styles — все правила элемента; перечёркнутые проиграли каскад
  • Computed — итоговые значения и откуда они пришли
  • Схема box model внизу панели — margin / border / padding / размеры
  • Значения можно править прямо в браузере, а потом перенести в файл
  • Device toolbar (Cmd/Ctrl+Shift+M) — проверка адаптива

Отступы и box model

Отступы

Способы задания отступов:

Порядок — по часовой: верх, право, низ, лево. 0 auto — центрирует блок с заданной шириной

padding — внутри рамки (фон виден), margin — снаружи

box-sizing

Bootstrap уже включает border-box для всех элементов

width: 200px — эталон
content-box (по умолчанию): 250px
ширина «съехала»
border-box: ровно 200px
ширина = width

Схлопывание margin

  • Вертикальные margin соседних блоков не складываются — берётся больший
  • Margin первого ребёнка может «выпасть» из родителя
  • Внутри flex и grid схлопывания нет

Практическое правило: отступы между блоками задаём в одну сторону (например, только margin-bottom, в Bootstrap — .mb-3) или через gap.

display
и position

Режимы отображения элементов

  • display: none ― элемент невидим, не занимает места
  • display: block ― занимает всю ширину, начинается с новой строки, учитывает width, height
  • display: inline ― занимает минимальную ширину, не прерывает строку, игнорирует width, height и вертикальные margin
  • display: inline-block ― блочный элемент, но не разрывает строку, примерно как img
  • display: flex / grid ― элемент становится контейнером и раскладывает своих детей

visibility: hidden — элемент невидим, но место занимает

Позиционирование

  • position: static ― обычный поток (по умолчанию)
  • position: relative ― смещение от своего обычного места; место в потоке сохраняется
  • position: absolute ― вынут из потока; отсчёт от ближайшего предка с position ≠ static, иначе — от документа
  • position: fixed ― относительно окна браузера, не прокручивается
  • position: sticky ― ведёт себя как relative, пока не «прилипнет» при прокрутке
  • top / right / bottom / left ― отступы, могут быть отрицательными
  • z-index ― порядок наложения (работает у позиционированных элементов)

Flexbox

Flexbox: основные понятия

  • Раскладка в одном направлении: строка или колонка
  • Flex-контейнер — элемент с display: flex
  • Flex-элементы — его прямые потомки
  • Главная ось (main axis) — направление раскладки, задаётся flex-direction
  • Поперечная ось (cross axis) — перпендикулярна главной

Свойства контейнера

gap вместо margin у каждого элемента: нет лишнего отступа у крайних, ничего не схлопывается.

Grid

Grid: основные понятия

  • Раскладка сразу в двух измерениях: строки и колонки
  • Grid-контейнер — элемент с display: grid
  • grid-template-columns / rows — размеры колонок и строк
  • fr — доля свободного места: 2fr 1fr = две трети и треть
  • grid-template-areas — именованные области
  • gap — промежутки между ячейками

Flex или Grid?

Flexbox

  • Одно измерение: строка или колонка
  • Размер определяется содержимым
  • Шапка, меню, кнопки в ряд, карточка «аватар + текст», центрирование

Grid

  • Два измерения сразу
  • Сначала сетка, потом содержимое
  • Каркас страницы, галереи, сетки карточек

Они отлично сочетаются: grid для каркаса, flex — внутри блоков. Сетка Bootstrap, кстати, построена на flexbox.

Адаптивная вёрстка

Начинаем с viewport

  • Без этой строки мобильный браузер рисует страницу шириной ~980px и уменьшает её — медиа-запросы не срабатывают
  • Ширины, на которых проверяем ДЗ: ≥1200px (десктоп), 768px (планшет), 375px (телефон)
  • Главный признак поломки — горизонтальный скролл

Проверка в консоли DevTools: document.documentElement.scrollWidth > innerWidth → true = что-то вылезло

Медиа-запросы

  • Mobile-first: сначала узкий экран, потом min-width для широких
  • Так устроен Bootstrap: .col-md-8 = «8 колонок начиная с md»
  • Вместо фиксированных width — max-width, %, fr

Картинки не вылезают за контейнер: img { max-width: 100%; height: auto; } (в Bootstrap — .img-fluid)

Footer прижат к низу экрана

Требование ДЗ: если контента мало, footer всё равно внизу окна.

position: fixed; bottom: 0 — не то: футер будет перекрывать контент на длинных страницах.

Bootstrap

Что такое Bootstrap?

Bootstrap — готовая библиотека стилей (CSS-фреймворк), изначально от Twitter. Позволяет быстро сделать аккуратный адаптивный интерфейс даже при базовых знаниях CSS.

В ДЗ используем Bootstrap 5.3 — getbootstrap.com/docs/5.3

Что включает в себя Bootstrap?

  • Шаблон страницы
  • Сетка
  • Современные «стили по умолчанию» (Reboot)
  • Утилиты: отступы, flex, цвета, размеры, …
  • Вёрстка: таблицы, формы, списки, кнопки, …
  • Компоненты: навигация, карточки, пагинатор, …
  • JavaScript плагины: выпадающие меню, модальные окна

Сетка Bootstrap

Правила сетки

  • .container → .row → .col-*, контент кладём только в колонки
  • В строке 12 колонок; больше 12 — колонка переносится на новую строку
  • .col-md-8 — 8 из 12 колонок начиная с ширины md, на меньших — 100%
  • .col — делим поровну, .col-auto — по ширине содержимого
  • Расстояние между колонками — .g-3, .gx-4, .gy-2
  • Колонку можно снова делить: внутри .col — новый .row

CSS и Bootstrap

Везде style="margin-left: 37px" Утилиты Bootstrap (ms-3, gap-2) или класс в style.css !important на каждой строке, чтобы перебить Bootstrap Свой CSS после Bootstrap + свой класс Правки прямо в bootstrap.min.css .row без .container, контент прямо в .row, сумма колонок > 12 container → row → col, всегда Фиксированные width: 1200px, height у блоков с текстом max-width, колонки сетки, высота — по содержимому

Адаптив и «мелочи»

На 375px шапка разъезжается или появляется горизонтальный скролл flex-wrap + gap + flex-basis у поиска Длинное слово растягивает карточку на всю страницу min-width: 0 у flex-элемента, text-break Footer висит посередине экрана или position: fixed закрывает контент min-vh-100 d-flex flex-column + mt-auto У лайков одно состояние, у пагинатора нет активной страницы Все состояния свёрстаны и видны в макете Блоки «слиплись» или отступы везде разные
