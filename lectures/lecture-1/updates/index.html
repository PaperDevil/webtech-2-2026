Internet и WWW

Internet

Internet — глобальная сеть сетей: тысячи независимых сетей, договорившихся об общих протоколах передачи данных

  • Нет единого центра управления
  • Данные передаются небольшими порциями — пакетами
  • Объединяет разнородные сети: Ethernet, Wi-Fi, LTE, оптику, спутники

Стек протоколов

  • Прикладной: HTTP, DNS — смысл данных
  • Защита: TLS — шифрование (HTTPS = HTTP + TLS)
  • Транспортный: TCP — надёжная доставка, UDP — быстрая
  • Сетевой: IP — глобальная адресация и маршрутизация
  • Канальный: Ethernet, Wi-Fi — передача в локальной сети

Подробно DNS, TCP, TLS и HTTP — в лекции 2

Ethernet

  • Технология локальных сетей (LAN)
  • Работает на канальном уровне (Data Link Layer)
  • MAC-адреса (48 бит) для идентификации устройств: 00:1A:2B:3C:4D:5E
  • Скорости: 10 Мбит/с → 100 Мбит/с → 1 Гбит/с → 10 Гбит/с → 100+ Гбит/с в дата-центрах
  • Основа для построения офисных и домашних сетей

IP - Internet Protocol

  • Обеспечивает адресацию узлов в сети
  • IPv4: адреса вида 192.168.1.1 (32 бита)
  • IPv6: адреса вида 2001:0db8:85a3:0000:0000:8a2e:0370:7334 (128 бит)
  • Маршрутизация пакетов между сетями
  • Работает поверх канального уровня (Wi-Fi, LTE, Ethernet)

IPv4 - Internet Protocol version 4

  • 32 бита, разделенные на 4 октета (десятичные числа от 0 до 255)
  • Всего доступно (около 4,29 миллиарда) адресов
NAT (Network Address Translation) — технология, преобразующая приватные IP-адреса локальной сети во внешние (публичные) для доступа в интернет, позволяя множеству устройств работать через один IP.

IPv6 - Internet Protocol version 6

  • Использует шестнадцатеричные числа, разделенные двоеточием
  • Поддержка IPsec рекомендательного характера
  • Упрощённые заголовки пакетов, которые проще и быстрее обрабатывать
  • 340 ундециллионов адресов:
    340 282 366 920 938 463 463 374 607 431 768 211 456 комбинаций

Внедрение идёт медленно — IPv4 живёт благодаря NAT.
Доля пользователей Google с IPv6

DHCP - Dynamic Host Configuration Protocol

  • Discover - широковещательный поиск серверов
  • Offer - сервер предлагает возможные настройки
  • Request - клиент принимает предложение конкретного сервера
  • Acknowledge - сервер подтверждает новые настройки

Выдаёт IP, маску, шлюз и DNS-серверы, исключает дублирование адресов. Постоянный IP — резервирование по MAC-адресу (static lease).

DNS - Domain Name System

  • Преобразует доменные имена в IP-адреса
  • Пример: google.com → 142.250.185.78
  • Иерархическая структура доменов
  • Распределенная база данных
  • Кеширование для повышения производительности

Проверить самому: nslookup google.com или dig google.com

World Wide Web

WWW - множество взаимосвязанных документов, располагающихся на машинах подключенных к Internet

WWW - набор протоколов, серверного и клиентского ПО, позволяющих получать доступ к документам

Internet ≠ WWW. Internet — это сеть, а WWW — лишь один из сервисов поверх неё, наряду с почтой, мессенджерами, онлайн-играми. WWW придумал Тим Бернерс-Ли в CERN (1989–1991).

URL и документы

URL - Uniform Resource Locator

http://server.org:8080/path/doc.html?a=1&b=2#part1
  • http - схема (протокол)
  • server.org - DNS имя сервера (или IP-адрес)
  • 8080 - TCP порт; по умолчанию 80 для http и 443 для https
  • /path/doc.html - путь к ресурсу (не обязательно файл на диске)
  • a=1&b=2 - строка запроса (query string), параметры
  • part1 - фрагмент (якорь), положение на странице; на сервер не отправляется

Кодирование URL

Всё, кроме латиницы, цифр и служебных символов, кодируется байтами UTF-8 в виде %XX:

  • пробел → %20 (в данных формы — +)
  • & внутри значения → %26, # → %23
  • ?q=веб → ?q=%D0%B2%D0%B5%D0%B1

Браузер показывает кириллицу, а по сети уходит закодированный вариант. Домены вида пример.рф кодируются иначе — Punycode.

Типы документов (MIME-типы)

  • text/html
  • text/css
  • text/javascript
  • image/png
  • video/mp4
  • text/xml
  • application/json
  • Полный список MIME типов

Тип документа сервер сообщает в HTTP-заголовке Content-Type. Расширения файлов играют второстепенную роль

Абсолютные и относительные URL

  • http://server.org/1.html - абсолютный
  • //server.org/1.html - относительный (схема берётся от текущего документа)
  • /another/page.html?a=1 - относительный (от корня сайта)
  • pictures/1.png - относительный (от URL текущего документа)
  • ../style.css - относительный (на уровень выше)
  • ?a=1&b=2 - относительный (от URL текущего документа)
  • #part2 - относительный (в пределах текущего документа)

Правила разрешения URL

https://site.com/path/page.html - основной документ

  • http://wikipedia.org = http://wikipedia.org
  • //cdn.org/lib.js = https://cdn.org/lib.js
  • /admin/index.html = https://site.com/admin/index.html
  • another.html = https://site.com/path/another.html
  • ../img/1.png = https://site.com/img/1.png
  • ?full=1 = https://site.com/path/page.html?full=1
  • #chapter2 = https://site.com/path/page.html#chapter2

Ловушка: слэш в конце пути

Путь отсчитывается от последнего / в URL документа:

  • https://site.com/docs + intro.html = https://site.com/intro.html
  • https://site.com/docs/ + intro.html = https://site.com/docs/intro.html

Что реально запросил браузер — в DevTools → Network.

Клиент-серверная архитектура

Клиент-серверная архитектура

Web-клиенты работают на компьютерах конечных пользователей. Задача Web-клиентов состоит в получении и отображении документов.

Web-сервера работают (как правило) на серверах в датацентрах. Их задача заключается в хранении (или генерации) и отдачи документов.

Преимущества подхода

  • Открытый протокол
  • Стандартный клиент
  • Прозрачный способ взаимодействия приложений
  • Распределенная и масштабируемая система

HTTP — язык общения клиента и сервера

Клиент отправляет запрос, сервер возвращает ответ. Это обычный текст:

Обратите внимание: фрагмента #part1 в запросе нет

HTTP: самое главное

  • Методы: GET — получить, POST — отправить данные
  • Коды: 2xx успех, 3xx редирект, 4xx ошибка клиента (404), 5xx ошибка сервера
  • Заголовки: Host, Content-Type, Cookie
  • HTTPS = HTTP + TLS: шифрование и проверка сервера
  • Stateless: каждый запрос независим

Что происходит, когда вы вводите URL?

  1. Браузер разбирает URL: схема, хост, порт, путь
  2. DNS: имя хоста → IP-адрес
  3. TCP: соединение с сервером по IP и порту (+ TLS для https)
  4. HTTP: браузер отправляет запрос, сервер возвращает ответ
  5. Браузер разбирает HTML и запрашивает CSS, JS, картинки — каждый по своему URL
  6. Браузер отрисовывает страницу

Разновидности web-клиентов

  • Библиотеки в ЯП: libcurl, urllib, requests и т.д.
  • Консольные утилиты: wget, curl, telnet
  • Роботы: поисковики, вредоносные скрипты
  • Браузеры:
    • Полноценные: Firefox, Chrome, Safari, Edge
    • Встроенные: web-view, webkit и т.д.

Как увидеть HTTP своими глазами

  • DevTools в браузере (F12) → вкладка Network: все запросы страницы, их заголовки, коды и время
  • curl в терминале:
    curl -v https://example.com/
  • Эхо-сервисы, которые возвращают ваш же запрос:
    https://httpbin.org/get?a=1

Сценарий работы web приложения

  • Пользователь вводит URL
  • Браузер загружает Web страницу - HTML документ
  • Браузер анализирует (parse) HTML и загружает доп. ресурсы
  • Браузер отображает (rendering) HTML страницу
  • Пользователь переходит по гиперссылке или отправляет форму
  • Цикл повторяется

Сценарий работы современного приложения

  • Браузер загружает Web страницу, ресурсы и отображает ее
  • JavaScript загружает данные с помощью AJAX запросов
  • JavaScript обеспечивает полноценный UI на странице
  • Пользователь взаимодействует с UI, что приводит к вызову JavaScript обработчиков
  • JavaScript обновляет данные на сервере или загружает новые данные, используя AJAX

HTML

Из чего состоит HTML

  • Элемент = открывающий тег + содержимое + закрывающий тег
  • Атрибуты (href, class) уточняют поведение элемента
  • Пустые элементы без закрывающего тега: img, br, input, meta, link
  • Элементы вкладываются друг в друга и образуют дерево (DOM)
  • Комментарий: <!-- не отображается -->

Структура документа

Теги верхнего уровня

  • <!DOCTYPE html> - включает стандартный режим отображения
  • html - обертка, атрибут lang задаёт язык страницы
  • head - служебная информация о странице, не отображается
  • body - тело страницы, то, что видит пользователь

Внутри head

  • meta charset - кодировка, первым элементом в head
  • meta viewport - корректное отображение на телефонах
  • title - заголовок вкладки и результата в поисковике

Вложенность и валидность

  • Браузер «прощает» ошибки и пытается угадать, что вы имели в виду, — каждый по-своему
  • Проверяйте разметку: validator.w3.org

Спецсимволы (HTML-сущности)

Символы, которые входят в синтаксис HTML, записываются через сущности:

  • &lt; → < и &gt; → >
  • &amp; → &
  • &nbsp; → неразрывный пробел
  • &copy; → ©

Кириллицу кодировать не нужно при charset="utf-8"

Блочные теги

  • h1 - h6 - различные уровни заголовков
  • p - разбиение текста на параграфы
  • hr - горизонтальная линия
  • pre - блок преформатированного кода
  • blockquote - цитирование длинного блока текста
  • div - абстрактный блочный контейнер

Строго говоря, «блочный» и «строчный» — это поведение по умолчанию, заданное в CSS (display), и его можно изменить

Семантические теги

  • header - шапка страницы или раздела
  • nav - навигация
  • main - основное содержимое (один на страницу)
  • section, article - раздел, самостоятельная статья
  • aside - дополнительный блок, сайдбар
  • footer - подвал

Выглядят как div, но сообщают смысл блока

Строчные теги

  • a - гиперссылки
  • strong - важный текст; b - визуальное выделение без особого смысла
  • em - смысловое ударение; i - термин, иностранное слово
  • img - вставка изображений
  • br - перенос строки
  • code - фрагмент кода
  • sub, sup - нижний и верхний индекс
  • span - абстрактный строчный контейнер

Списки

ul - маркированный список

ol - нумерованный список

Внутри ul и ol могут быть только li. Списки можно вкладывать: новый ul — внутри li. Меню сайта — это тоже список.

Таблицы

  • tr - строка, th - ячейка заголовка, td - ячейка
  • Таблицы — для табличных данных, не для вёрстки макета

Изображения

  • src - URL картинки (абсолютный или относительный)
  • alt - текстовое описание: показывается, если картинка не загрузилась, и читается экранными чтецами. Обязателен
  • width, height - размеры; браузер заранее резервирует место

Гиперссылки

  • href - URL гиперссылки
  • target - в каком окне открывать ссылку
  • id - уникальный идентификатор, может использоваться как якорная точка

Какие бывают ссылки

Формы

Форма собирает данные пользователя и отправляет их на сервер HTTP-запросом:

После отправки браузер перейдёт на
https://httpbin.org/get?q=введённый+текст

Атрибуты формы

  • action - URL, на который будет отправлена форма (по умолчанию — текущий)
  • method - HTTP метод, GET (по умолчанию) или POST
  • enctype - способ кодирования данных формы:
    • application/x-www-form-urlencoded - по умолчанию
    • multipart/form-data - только когда нужно передать файлы
  • target - где открыть результат (_self, _blank), используется редко

Элементы формы

  • input - универсальное поле, вид задаёт type:
    • text, email, password, number, date
    • checkbox - да/нет, radio - один вариант из нескольких
    • file - загрузка файла, hidden - невидимое поле
  • textarea - многострочное поле ввода
  • select, option - выпадающий список
  • button - кнопка (type="submit" отправляет форму)
  • label - подпись к полю

Атрибуты полей ввода

  • name - имя, под которым значение попадёт в запрос. Без name поле не отправится!
  • value - начальное значение
  • placeholder - подсказка внутри пустого поля
  • required, minlength, min/max - проверка в браузере
  • checked, selected, disabled - состояние поля

Подписи: label

Клик по подписи ставит фокус в поле или переключает чекбокс. Экранные чтецы читают подпись вместе с полем.

Пример формы с файлом

GET или POST?

GET

  • Данные в URL: ?q=web
  • Видны в истории
  • Можно поделиться ссылкой
  • Поиск, фильтры

POST

  • Данные в теле запроса
  • Не попадают в URL
  • Подходит для файлов
  • Создание, изменение, логин

POST — не шифрование! Защищает только HTTPS

Допустим есть форма со следующими данными: В закодированном виде это будет выглядеть так: id=3&name=%D0%92%D0%B0%D1%81%D1%8F&friend=4&friend=5

CSS

Cascading Style Sheets

CSS позволяет описывать внешний вид отдельно от структуры документа

Где могут быть заданы стили?

  • Встроенные в браузер стили
  • Во внешнем файле
    <link rel="stylesheet" href="style.css">
  • В коде HTML документа
    <style>...</style>
  • Стили могут быть привязаны к конкретному тегу
    <img style="margin: 3px" src="...">

Базовые селекторы

  • Универсальный селектор
    * { margin: 0; padding: 0; }
  • Имена тегов
    p { margin-top: 10px; }
  • Имена классов (с точки)
    .btn { border: solid 1px gray; }
  • id тегов (с решетки)
    #userpic { padding: 10px }

Режимы отображения элементов

  • display: none - элемент невидим, не занимает места
  • display: block - элемент занимает максимальную ширину, начинается с новой строки
  • display: inline - элемент занимает минимальную ширину, не прерывает строку
  • display: inline-block - блочный элемент, но не разрывает строку
  • display: flex, display: grid - современная раскладка дочерних элементов в строку, колонку или сетку

Bootstrap

Bootstrap - это готовая библиотека стилей (CSS-фреймворк), изначально созданная в Twitter, сейчас — самостоятельный open-source проект. Bootstrap позволяет быстро разработать приемлемый дизайн даже при базовых знаниях CSS.

Что включает в себя Bootstrap?

  • Шаблон страниц

  • Современные «стили по умолчанию»
  • Верстка: таблицы, формы, списки, кнопки
  • Компоненты: навигация, меню, пагинатор
  • JavaScript плагины

  • Application сервер возвращает чистые данные (JSON)
  • Фреймворки: React, Vue.js, Angular

Итоги

  • Internet — сеть сетей, WWW — сервис документов поверх неё
  • URL однозначно указывает на ресурс; относительные URL разрешаются от текущего документа
  • Браузер и сервер общаются по HTTP: запрос → ответ
  • HTML описывает структуру, CSS — внешний вид, JavaScript — поведение
  • Формы отправляют данные на сервер методами GET и POST
